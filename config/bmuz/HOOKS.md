# BMUZ hooks — rules the computer enforces (F68 + F67, 2026-10-18 · one file per rule since F184, 2026-11-04)

A **hook** is a small script Claude Code runs by itself before or after one of Claude's actions. It can stop the
action and tell Claude why. Unlike a rule written in CLAUDE.md or a skill (which Claude has to remember), a hook
always runs (①). Scripts: `~/.claude/config/bmuz/hooks/` · wiring: `~/.claude/settings.json`.

**How they're built (F184).** Each rule is its own small file, `hooks/rules/<hook>/<ID>.<name>.mjs` — its id, what it
does, why (with Muzzy's words where there are some), on/off, and the test suite that proves it. `rules/<hook>/_hook.mjs`
says when the hook runs and in what order its rules are checked. The hook files `settings.json` starts (guard-git.mjs,
handoff-check.mjs, …) are 4-line starters that hand over to `hooks/runner.mjs`. Every answer goes into the firing log
(`~/.claude/logs/bmuz-hooks.jsonl`) with the rule's id. To change a rule: edit its file, run
`node ~/.claude/config/bmuz/hooks/test-hooks.mjs`, then `node ~/.claude/config/bmuz/scripts/hooks-doc.mjs` (rewrites the
table below). To switch one off: `on: false` in its file.

**Never silent (F184).** ① A rule that crashes, or a rule file that won't load, is skipped — the other rules still
run — and Claude (and Muzzy, on screen) is told which rule broke; the firing log gets a "crash" line. If a shared file
(`lib.mjs`, `runner.mjs`) breaks, `hooks/fallback/broken.mjs` answers instead, saying "BMUZ hooks are broken: …":
before a tool call it **refuses** (a guard that can't run must not wave a force-push through) — except anything
touching `~/.claude/config/bmuz` or `~/.claude-config`, so the fix can be made · after a tool call, a message beside the
result · when Claude finishes, sent back once (then only the message, never a loop) · when Muzzy types, a note — his
message still goes in. (2026-11-04: one typo in lib.mjs had silently turned every hook off for ~20 minutes.)

**Commit checks inside git too (F184).** The commit rules (GG4, GG6, GG8–GG13, CT1, CT2) also run in git's own
commit step: `config/bmuz/git-hooks/commit-msg`, set **per BMUZ project, never globally** (`git config core.hooksPath`,
done by save.mjs; a repo with its own hooks — husky, lefthook, an existing core.hooksPath — is left alone and named;
`collabs/` is never touched). There they see the real staged files and message, so a commit made by any tool or script
is checked too. GG14 refuses `--no-verify` so the step can't be skipped (Muzzy can still `! git commit --no-verify`).

**The firing log (F181):** each time a hook refuses, asks, sends a turn back or tells Claude something, one line ① (lib.say)
goes into `~/.claude/logs/bmuz-hooks.jsonl` (this machine only, not synced): `{t, hook, event, kind: deny|ask|block|context|stderr,
project, text (first 300 chars), src: "live"}`. Silent passes aren't logged. It's for the audit and /checkup: which hooks
fire, how often, and which fire falsely. Every answer goes out through `say()` in hooks/lib.mjs (deny / ask / tellClaude /
stopVerdict use it; session-start notes use `tellSession()`), so a hook never writes stdout itself ① (test-hooks
"fire-log" fails on a hook that does). Logging errors are swallowed, so the answer stays the same ① (lib.logFiring); past ~5 MB the file
becomes `bmuz-hooks.1.jsonl`. Tests send it elsewhere with `BMUZ_FIRE_LOG`.
**Before the log:** `node ~/.claude/config/bmuz/scripts/hook-history.mjs` reads every past session transcript
(`~/.claude/projects/`, helpers' too) and writes the same lines with `src: "history"` + the session file to
`~/.claude/logs/bmuz-hooks-history.jsonl` (rewritten each run), then prints per hook: counts by kind, how many sessions it
fired in, its 5 most frequent texts. A crashed hook shows as `stderr` there (the live log can't see a crash).
