# BMUZ hooks — rules the computer enforces (F68 + F67, 2026-10-18)

A **hook** is a small script Claude Code runs by itself before or after one of Claude's actions. It can stop the
action and tell Claude why. Unlike a rule written in CLAUDE.md or a skill (which Claude has to remember), a hook
always runs (①). Scripts: `~/.claude/config/bmuz/hooks/` · wiring: `~/.claude/settings.json`.

## Scripts — fragile jobs as one command (F69)
A **script** (①) does a whole multi-step job the same way every time — or refuses before changing anything, saying why in
plain words. The skills call them (①); you never need to type them. Folder: `~/.claude/config/bmuz/scripts/`.

| Script | Does | Refuses when |
|---|---|---|
| `install-module.mjs <module> <game>` ① | Installs / updates a framework module (any framework folder with `kit/VERSION` + `"bmuz": { "folders" }` in its package.json counts too — F114): the module's own tests first, the dry run, the install (+ the module's folders into the game's eslint `globalIgnores`, F112), then that module's checks and the game's OWN lint in the game | the module's own tests or checks are red · the game's eslint.config can't be edited safely (gives the line to add) · the game doesn't keep the module's promises yet (says what to wire) · the game's own lint fails |
| `extract.mjs add \| list \| status \| fix \| swap` ① (F114, Muzzy only) | The extraction queue (PROJECT-FILES "Extraction queue"): a game queues a finished piece at its commit · the framework marks it building / released `<module>@<version>` · bug fixes to frozen files are logged · `swap` installs the module, points the game's imports at it, deletes the old files, runs the entry's checks unchanged → one game commit. Each queue change is committed in the framework (through guardCommit). Red swap → the attempt kept on `extract/<id>-swap`, the game switched back untouched | add: a missing / uncommitted / already-queued file, a check that isn't a game script · status: no such module or version, uncommitted module code · swap: not released, an unclean tree, a queued file changed with no fix logged |
| `release.mjs <update\|milestone\|stage\|major> "<summary>"` ① | Checks every /deliver gate FIRST and lists all failures at once (GitHub green, check:fast + check:framework, STATE log/RESUME/`Release:`, no code since the full check / review / security review, no open P0, features ✅, sprint archived, milestone ✅, musts, and for a stage/major release a playtest log in `.planning/research/playtests/` dated since the last stage release ① — F87) — `--dry-run` only checks. Then version bump, history line, package.json, STATE `Version:`, the `Release vX.Y.Z` commit (a stage release's body says `Stage: <stage>`) and tag, cleanup.sh — never pushes. Overrides (`--unapproved-ok`, `--musts-open-ok`, `--no-playtest-ok`, `--stage=`) are Muzzy's calls and are written into the commit body | any gate fails (all named) |
| `merge.mjs <branch>` ① | /deliver §4 in one go: push the branch → GitHub green → checkout main → pull → `git merge --no-ff` → delete the merged branch (GitHub's copy after live-check). version.json conflicts settle themselves; never pushes main. guard-git lets it run only during /deliver | uncommitted code · no such branch / it IS main · GitHub red · a real conflict (lists the files, leaves the two ways out) |
| `live-check.mjs [--url=…]` ① | After the push: waits for the deploy run, fetches the live page (cache-buster) until it's public and has the new version, runs `e2e:update` / `smoke:live` when the game has them, writes `.planning/live-pass` (commit · `tag url` · time · console method), deletes merged branches on GitHub. `Release: none / not set up / blocked` → records the skip. The Stop hook sends a release turn back until live-pass names the new tag | no `Release:` line · deploy red · page not public or not the new version |
| `rollback.mjs <tag> ["why"]` ① | Puts a released version's code back as ONE new commit on main (never rewrites history); keeps `.planning/` and version.json; prints what still needs doing (smoke, release, push, server redeploy). guard-git lets it run only during /deliver | uncommitted code · not on main · no such tag · the code already is that tag's |
| `save.mjs "<summary>"` ① | Runs cleanup.sh first (its 🧹 line shown; a failing cleanup only warns — F78), adds a BMUZ project's missing `.gitignore` lines (`.claude/worktrees/`, `.planning/ppp.html`) and says so, build +1, old Log lines to the archive, commit, push — and "safe to switch machines" only once GitHub has the commit | a `.env` or secret would be committed · the push failed (says NOT safe) |
| `archive-sprint.mjs` ① | Files a finished sprint and commits `Sprint NN done` | a feature isn't approved yet · no `Retro:` with all three lines — went well · went wrong · change (F81; says to ask Muzzy) |
| `musts-check.mjs <stage>` ① | Lists the `must:<stage>` features still open before a release | — (exit 1 = some open) |
| `stop-servers.mjs <port\|name>` ① | Ends a local server's whole process tree (on Windows, killing only the port lets wrangler restart it) | — (never touches Claude, a shell or an editor) |
| `cleanup.sh [project]` (bash) ① | Finished helper workspaces, old check output, temp files — and Claude's scratch place `~/Documents/dev/.scratch/<project>-<what>/` (throwaway game copies, proof shots): entries untouched for 24 h go (F78). Never a tracked file | — (keeps and names anything that still holds work) |
| `templates/check-all.mjs` (in each game) ① | A full check run takes a lock; then the port pre-flight (F118): every port the run's e2e scripts use (numbers in the E2E args, each script's `const PORT = …` and `// ports: …` lines) must be free. Needs `scripts/ports.mjs` (from `templates/ports.mjs` — the same who-holds-this-port lookup stop-servers.mjs uses). checkup §7 and install-module.mjs name a game's older copy | another full check run is still going · a port is held → names the port, the script, the holder's command + folder and `stop-servers.mjs <port>`, before anything starts |
| `checkup.sh --done` (bash, F80) ① | Closes a /checkup: writes today's date to `last-checkup`, then `config-sync.sh push` (the laptop gets it) | today's report isn't saved in `reviews/checkups/<date>.md` |

**Script commits get the commit hooks too (F80):** save.mjs and release.mjs ask guard-git + commit-typecheck about their
own commit first (`guardCommit` in scripts/lib.mjs) — secrets, `F08:` code on main, `F08: done` gates, type errors,
the stage-commit and bug-fix rules — because a commit made inside a script is invisible to the shell hooks.

**Proof:** `node ~/.claude/config/bmuz/scripts/test-scripts.mjs` (throwaway repos; real servers for stop-servers).

**The smoke pass (hook 4):** `node ~/.claude/config/bmuz/hooks/smoke-pass.mjs` in the project runs its `smoke` npm
script (the game loads and one turn/round plays, console clean) and, only if it passes, writes `.planning/smoke-pass`
(the commit it tested). Commit that file, then push. /deliver does this right before the push. A game without a `smoke`
script gets told to add one (point it at an e2e that already plays a round).

**Proof:** `node ~/.claude/config/bmuz/hooks/test-hooks.mjs` — feeds every hook "should refuse" and "should allow"
cases in throwaway repos (425 checks, ~3 min). Each hook was also tried for real in a headless Claude session (2026-10-18).
Changing a hook → also try it with the chained commands Claude really types (`git add -A && git commit`, `commit && push`):
a hook sees the whole line BEFORE any of it runs — the commit gate's first real try slipped through that way.

**Real tries (a new or changed hook isn't done until one passes):** in a throwaway repo in the scratchpad, ask a
headless Claude to do the thing the hook should catch, then read what it did — `echo "<task>" | claude -p --allowedTools
"Bash Edit Write Read Glob Grep"` (the prompt goes in through stdin), then check the repo (`git log`, the file) and the
session log in `~/.claude/projects/<folder>/` for the hook's message. Each one caught something the unit tests didn't:
2026-10-18 a file made and committed on ONE line slipped past the main-branch rule (the file didn't exist yet when the
hook looked); the sprint nudge sent Claude looking for SPRINT.md in the wrong folder (now names the full path).

**Plan files by hand:** `node ~/.claude/config/bmuz/hooks/plan-lint.mjs <project>` lists every problem (the hook itself only mentions new ones). It only reports — it never trims the Log (a check doesn't edit what it checks); the hook and save.mjs do ① (plan-lint.mjs, save.mjs).

**Switching one off:** delete its block in `~/.claude/settings.json` (hooks 1, 3–13, 15–18, 20–24 — the PreToolUse/PostToolUse/UserPromptSubmit/Stop
entries; 19 and 25 live in session-start.sh); type `/hooks` to see what's loaded.
Everything goes to the laptop with /sync.
