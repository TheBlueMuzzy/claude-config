# BMUZ-2 — where it's going (read this at the start of any BMUZ-improvement session)

## The vision
BMUZ is Muzzy's way to build games fast as a designer/artist who's only somewhat technical: he designs, Claude builds, and the process stays mostly invisible.
The long-term heart of it is a **Game Framework** (like the one at PlayTable/TapTop, where Muzzy was creative director): a library of easily modified **modules**. Starting a new game, Claude reads the GDD, **infers the modules it needs** (AI opponents, multiplayer, card hand…) and the project gets its bones automatically. Muzzy is only asked about genuine choices.
His games so far are deliberately varied to prove out which modules are needed. Roll Better ≈ beta, a testbed — not a game to keep polishing.

## Lessons from the Roll Better UI revamp (2026-09-29, autonomous run) — game-ui improvements to make
Applied to skills 2026-09-29; open items = next framework kit pass.
Running list, added as they come up. Each line: what slowed us down → what the skill/kit should do instead.
- Kit overlay covers the whole window, but games letterbox to 16:9 → corner slots (version, HUD) landed in the black bars. → Kit should support a "game box": `--game-w/--game-h` (or a `frame` prop on ScreenStack) so screens size to the game frame while the dim still covers the window. Roll Better fixed it in its own CSS (F50); fold it into the kit. → applied in kit 0.1.7 (game box)
- Game was 2 kit versions behind (0.1.3 vs 0.1.5) and nobody noticed. → /develop (or game-ui step 2) should compare `src/ui/kit/VERSION` with the framework's at the start of any UI task and offer the update. → applied in skills/develop/SKILL.md §1
- Plan said "build the new piece in the game, copy back later" — the game-ui skill says the opposite (framework first). → /define's build-plan stage should read the game-ui rules when a feature needs a new kit piece, so the plan never contradicts them. → applied in skills/define/stages/build-plan.md + skills/sprint/SKILL.md
- `Avatar` had no player-colour prop; Lobby shows every player the same colour. → Multiplayer kit parts should take a per-player colour from day one (added in 0.1.6). → applied in kit
- Lists inside panels overlapped their captions on phone landscape (844×390) — in Lobby since 0.1.x, found only when SeatPicker was built. → `npm run shoot` should include phone landscape for every screen (landscape games are common); fixed once in kit.css (0.1.6). → partly: shoot covers 6 landscape screens; every screen → next framework kit pass
- A taste call (menu backdrop colour) needed a question to Muzzy. → The Dev Kit Color tool (style.json swatches + pickers) removes the question entirely; make it the first Dev Kit tool any kit game gets. → applied 2026-09-29: Dev Kit is framework module `devkit/` (0.1.1) with installer; Color tab ships with it
- Kit `MainMenu` has a fixed button order (continue, play, settings, how to play…) → Roll Better had to put "Play" in the `continue` slot and "Play online" in `play`. → MainMenu should take an ordered list of `{ label, onClick, primary? }` items. → applied kit 0.2.0 (`items`)
- Kit `Lobby` assumed every game has a Ready step, had no copy-code and no Back on the join card → games stitched extra `Screen` slots on top. → Fixed generically in kit 0.1.7 (optional Ready, copy code, onBack, player colours). General rule: when a game needs a stitch, it's a kit gap — log it for the framework in the same session. → applied in kit 0.1.7; rule already in game-ui ("Nothing one-off in the game")
- Old docs were stale about the menu (a player-count picker that didn't exist). → When a screen moves onto the kit, the helper should diff old behaviour from the code, not the docs, and note "behaviour kept / changed" per screen (Roll Better's helper did this well — make it a game-ui step). → applied in skills/game-ui/SKILL.md step 2
- Kit styles only applied inside kit screens/page/toasts/overlay — each with its own layout — so a kit part pinned onto a 3D scene (drei Html) had nowhere neutral to live. → `.kit-scope` (base styles, no layout) added in kit 0.1.8. Pattern for 3D games: kit PlayerChip (engine-free) + a tiny game-side `Pinned` wrapper (drei Html) — the kit never imports three/R3F. → applied in skills/game-ui/SKILL.md step 3
- Kit parts are sized in rem, but anything pinned to a 3D table must scale with the table (window size, camera distance) → Roll Better's `Pinned.tsx` measures scale by projecting points (drei's distanceFactor ignores window size/off-centre) and fits kit parts to a box. → Move a "pinned kit part" helper (engine-neutral scale input + an R3F adapter) into the framework; it's the pattern every 3D kit game needs. → applied kit 0.2.0 (`PinnedBox` + R3F adapter in CATALOG)
- drei Html mounts outside the canvas's parent → kit scopes/z-index didn't reach it; cost a debugging loop. → Document in the game-ui skill: pinned kit UI needs `.kit-scope` + its own z-index layer. → applied in skills/game-ui/SKILL.md step 3
- check-ui only scans `src/ui/`, but layer/placement workarounds ended up in `App.css` unchecked. → Checker should also scan the game's CSS for rules that restyle kit classes. → applied kit 0.2.0 (`check-ui --css src`)
- Kit gaps logged by the in-game move (worked around in the game): Results has no dim option; toasts only top-centre (game wanted them over the rolling area); RoundIntro catches taps; icon buttons have no glyph size (gear tiny); no plain-text HUD chip; Bar has no width; PlayerChip badge forces a 2nd line (too tall for tight rows → bots shown as "B2" in the avatar instead); no "pop" when a chip's detail changes. → Next framework pass: kit 0.1.9 with these. → partly applied in kit 0.1.9–0.1.11 (HudText, bigger icon buttons, RoundIntro plain, pop); Results dim, toast placement option, Bar width, chip badge line → applied kit 0.2.0
- Phone landscape rows are ~39 px apart → any per-row UI has ~9 px detail text. → game-ui should flag "per-row UI on phone landscape" as a density risk at plan time, and PlayerChip should have an `xs` size that drops the detail line. → density flag applied in skills/game-ui/SKILL.md step 3; PlayerChip xs → applied kit 0.2.0
- Overnight autonomous run worked: framework-first kit pieces in parallel with game work, one big game helper per sprint, a Monitor on SPRINT.md ticks for progress bars. → Make "framework helper ∥ game helper" the default /develop pattern for UI sprints. → applied in skills/develop/SKILL.md §2
