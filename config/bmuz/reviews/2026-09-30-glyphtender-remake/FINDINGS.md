# BMUZ stress test — Glyphtender web remake (started 2026-09-30)

Muzzy's brief: remake Glyphtender (Unity) as a web game *to challenge BMUZ and find where it can improve*. Every time BMUZ is missing something, contradicts itself, or makes the work harder, it gets logged here with a proposed fix. Nothing in BMUZ changes without Muzzy's OK — this is the evidence list for that conversation (and for /checkup).

Severity: 🔴 blocked or caused real waste · 🟡 friction / had to improvise · 🟢 nice to have

## Log

### Discover (2026-09-30)
1. 🟡 **No remake procedure.** BMUZ has "new project" and "convert old GSD project" but not "remake an existing game on a new platform". Had to improvise from the DoomDial precedent (rename old → `-original`, fresh repo), which itself stalled after one commit. *Fix:* a short "Remake" section in SETUP-AND-CONVERT: rename old repo + folder, new repo, `research/original-digest.md` (rules / systems / soul / known bugs, code beats docs), treat the original as read-only, /discover focuses on *what to improve* rather than *what the game is*.
2. 🟡 **Folder rename blocked by the session's own working directory** ("Device or resource busy") until the shell moved out of it. *Fix:* the remake procedure says "cd to the parent first; if it's still locked, close Unity/Obsidian/Explorer windows on it."
3. 🟡 **`/discover` stage assumes a blank-slate idea** (ask what the idea is, who'd play it…). For a remake most of that is known; the real discovery questions are *what's wrong with the old one, what do other games do better, which platform/layout targets*. *Fix:* a remake branch in `stages/discover.md`.
4. 🟡 **No web-game starter.** Setup only covers planning files; the Vite/React/TS/PWA/CI/PartyKit/vitest/e2e skeleton exists only as "copy Roll Better". Toolchains already differ (framework: Vite 8 / TS 7 / vitest 5; Roll Better: Vite 7 / TS 5.9 / vitest 4) and nothing records the baseline. *Fix:* a framework `starter/` module (or `create-game` script) that scaffolds the skeleton with the current baseline + kit + Dev Kit wired in.
5. 🟡 **ai-opponent skill is instructions only**, puts personalities in `src/` (breaks the "tweakables live in content/" rule), doesn't mention the Dev Kit AI tool or its own source (Glyphtender's `festive-booth` branch), and its "ask the user" step clashes with "decide engineering calls myself". *Fix:* becomes a framework `ai/` module during this remake (see GDD scope); skill then says "install the module".
6. 🟢 **The real AI reference lived on an unmerged branch** (`festive-booth`) while `main` and HANDOFF disagreed. Old docs claimed "implemented". *Fix:* the remake digest step should check branches, not just main (done here).
7. 🟡 **UI kit has no board/tile parts** (tile rack, letter tile, board viewport with pan/zoom, drag-to-slot). Word/board games are a big share of Muzzy's catalogue (Glyphtender, Mahjong research, Roll Better's drag-to-zone). *Fix:* game-side first, harvest into the kit once proven (framework rule: prove in a game first).
8. 🟢 **Version drift across framework docs** — Dev Kit shown as 0.1.0 / 0.1.1 / 0.2.0 in different files; Roll Better TDD/GDD headers stale; BMUZ-PLAN says Roll Better v0.4.0 (it's 0.4.1). *Fix:* /checkup could diff stated versions against VERSION files.
9. 🟢 **Conflicting doc rule**: SETUP-AND-CONVERT says "no VISION.md" but its conversion step 7 moves ideas *to* VISION.md, and DoomDial created one (which also refers to the old `/game-discover` name). *Fix:* pick one (ROADMAP → Ideas) and fix step 7.
10. 🟢 **e2e isn't in CI and has no shared harness** — each game rolls its own `e2e/lib.mjs`, ports collide. *Fix:* candidate framework module alongside the starter.
11. 🔴 **Renames break the two-machine sync.** After renaming a repo/folder on one machine, the other machine still has the old clone under the *new* project's name; its session-start `git pull` would happily keep updating the wrong game there. Needed a hand-written warning in global CLAUDE.md. *Fix:* the session-start hook checks that each `dev/` folder's remote matches HUB.md and flags mismatches ("games/glyphtender points at glyphtender-original — fix?"); HUB.md becomes the source of truth for folder ↔ repo.
12. 🟡 **HUB.md isn't in any repo** (`dev/` isn't git), so the hub index doesn't travel between machines either. *Fix:* keep HUB.md in the synced `~/.claude` config (or a tiny `dev-hub` repo).

### Define (2026-09-30)
13. 🟡 **No "feel test" / spike feature type.** Muzzy asked, unprompted, to try the undo-until-Cast flow in a throwaway mini-proto before committing to it. BMUZ has ❓ decisions (answered by talking) and `proto` (Python odds sims), but nothing for "build a 1-hour interactive toy to decide how something *feels*". Designers decide feel by touching it. *Fix:* a 🧪 **feel test** type — a tiny playable toy on a `spike/` route, answers one ❓, thrown away or promoted; /define suggests one whenever a ❓ is about feel.
14. 🟢 **Scope table doesn't scale.** GDD §7 is one table with a column per release + Should/Could/Won't — at 7 columns × 10 rows it's unreadable in Obsidian and rows don't mean anything across columns. *Fix:* one short bullet list per release column instead of a table.
15. 🟢 **Multi-choice questions need a plain-English "what this means" line.** Muzzy picked "One Cast button + free undo" while saying he didn't quite understand it. The option text was written for someone who knows board-game apps. *Fix:* in AskUserQuestion options, describe the *felt* difference ("tap, it moves; change your mind, tap again"), not the pattern name.
16. 🔴 **"Prototype" means two things.** BMUZ's release ladder starts at *prototype*; to Muzzy a prototype is a throwaway **code sketch** that proves one concept ("the real 'code illustration work of art' is created from what you learned, but it doesn't need to use the code from the code sketch"). Finding 13's "feel test" is just *his* word "prototype". *Fix:* releases = alpha → beta → 1.0; add a 🧪 **prototype** feature type (code sketch, answers a ❓, lives in `sketches/`, learnings → GDD/TDD, code not reused unless clean). Update PROJECT-FILES planning model + /define + /develop.
17. 🟡 **I over-read old docs over the designer's current voice.** I framed the game as "hunt your rivals" from HANDOFF/transcript quotes; Muzzy: "it's not about hunting. it's a cozy game." and gave the real theme (Grand Glyphtender, Glyphwood Gardens, topiary letters, Magic = points). Also put AI in alpha though he'd said AI comes after pass-and-play + online. *Fix:* the remake flow's first /discover question should be "tell me the theme and fantasy in your words, today" — old docs are evidence about *mechanics*, not about *tone*. And /define should read back the release order in one line before writing scope.
18. 🟡 **UI kit styles have no night/dark variant.** Muzzy wants Cozy at night (so Magic sparkles pop); Cozy is light paper. Doable with colour tweaks in the game's style.json, but "dark version of my style" will come up in most games. *Fix:* each preset gets a `night` colour set (`{preset:"cozy", mode:"night"}`), previewed on the pick sheet.
19. 🟡 **Compliance checklist misses content licences.** The TDD template asks about fonts/sounds/images/code but not *data* — Glyphtender's word list is TWL (owned by NASPA/Hasbro). Caught only from general knowledge. *Fix:* add "word lists, dictionaries, datasets, map/level data" to TDD §7 and indie-toolkit lights.
20. 🟢 **Feature IDs vs. build order.** Muzzy already knew the prototype as "F01", but it needs the project skeleton first, so F01 needs F02. Harmless, but IDs read like order. *Fix:* none needed — just say "IDs are names, not order" once in /roadmap's output.
21. 🔴 **Data assets lost their story.** The word list represents days of Muzzy's work (source choice, cleanup, +218 words, Zipf column driving AI difficulty) but nothing in the repo said so — HANDOFF just says "standard word list". Both the digest helper and I treated it as a swappable file and flagged "swap to ENABLE" as if that were cheap. Muzzy had to step in. *Fix:* the remake digest (and /tdd) gets a **"precious data"** section: every hand-built data asset (word lists, level data, balance tables) with its history from `git log --follow`, what depends on it, and "carry over unchanged unless Muzzy says". Never propose replacing one without first tracing its history.
22. 🟢 **Code comments lied about the data.** "Zipf ≥3 ≈ 5k words" — really 22k. Nobody measured. *Fix:* where a design number depends on data, a test asserts the count (e.g. "Apprentice vocabulary is 4k–7k words") so drift shows up.

### Develop — Sprint 01 (2026-09-30)
23. 🟢 **Sprint/Dev Kit wording mismatch.** /sprint says "first task scaffolds the project … then gets the Dev Kit", while my roadmap had put the Dev Kit in F03 with the UI kit. Moved it into the skeleton. *Fix:* /define's build-plan should put the Dev Kit in the skeleton feature by default (Tier 1 = from the first playable) — and a prototype benefits from it most.
24. 🟡 **/develop's "run /code-review on every feature" doesn't fit prototypes** (throwaway code sketches). Skipped with a note. *Fix:* once 🧪 prototype exists as a type, exempt it from review; review starts with the real build.
25. 🟡 **Layout checks need an overflow/clipping assertion, not just screenshots.** The tray clipped on a 390 px phone; I caught it by eye, then added a scripted "nothing past the screen edge" check. game-ui step 7 relies on screenshots only. *Fix:* a shared e2e helper (`assertNothingClipped(page)`) in the framework, run at 390×844 / 844×390 / 1440×900 by every game's layout check.
26. 🟡 **No "piece state language" in the framework.** Muzzy caught that a planned seed had a ring but the planned glyphling didn't. The UI kit standardises menus/HUD, but nothing standardises in-world piece states (options · held · planned · done · disabled · opponent's). Every board/card/dice game needs the same set. *Fix:* a small framework spec + tokens (colours/rings/opacity per state) that game pieces use, checked the way check-ui checks raw colours; /develop's visual check asks "does every state look the same across piece types?"
27. 🟢 **Story beats should be asked for in /define.** Muzzy's feedback on a working flow was about the *fiction* (the glyphling throws the seed; it grows). /define captured the theme but not "what should each action look like happening". *Fix:* Design part asks, per core verb: "what does the player *see happen* when they do it?" — one line each, into GDD §4 Controls.
28. 🟡 **UI kit ships every style's fonts.** A Cozy game caches ~118 KB of fonts it never uses (Nunito alone is 39 KB). *Fix (framework):* install-kit copies/loads only the chosen style's fonts.
29. 🟡 **Kit Settings wastes phone-landscape height.** At 844×390 the tab picker wraps to two rows and only ~1.5 setting rows show before scrolling (seen first-hand in the screenshot). *Fix (framework):* in `max-height: 30rem`, tabs become a single scrolling row or a side list; panel uses the full height.
30. 🟢 **Word Play research → reusable style guides** — see `wordplay-style-ideas.md` next to this file (feedback tiers touch → payoff, reveal pacing, dark-theme colour rules, menu layout). Candidate BMUZ reference card.

### Develop — Sprints 02–03, autonomous overnight (2026-09-30)
31. 🟡 **Kit has no way for a game to feed its own CSS a tuned number or colour.** check:ui rejects any CSS variable that isn't a kit token, so board/tray sizes and garden colours (content/tuning) had to become SVG attributes. Fine for SVG, awkward for anything HTML. *Fix (framework):* allow a `--game-*` prefix that check:ui accepts only when set from content/ values.
32. 🟡 **Kit has no player-colour text/chip.** Every multiplayer game needs "Yellow's turn" in yellow. Worked around with an Avatar + plain text. *Fix (framework):* a `PlayerTag`/`tone="player-n"` on Text/Badge fed by the game's player colours.
33. 🟢 **Screenshot folders drift.** Three e2e scripts, three default output folders (one inside the repo, not git-ignored until I caught it). *Fix:* shared e2e helper (see #25) owns the output folder (always the scratchpad or a git-ignored `e2e-shots/`).
34. 🟢 **Autonomous pattern that worked:** one big game helper per sprint + one independent "correctness reviewer" helper per sprint (write the failing test first, then fix). The engine review found 1 real bug the builder's 83 tests missed. Worth making the reviewer a standard /develop step (it's what "/code-review low" was meant to be, but a helper that proves bugs with tests is stronger).
35. 🟢 **I still catch layout issues by eye that automated checks don't** (empty band between board and tray on portrait). The clipping check can't see "wasted space". *Fix:* game-ui's screenshot step names common layout smells to look for: dead bands, controls far from thumbs, text wrapping onto its own line.
36. 🟡 **Framework-first + "don't merge without Muzzy" = games installed from an unmerged branch.** Glyphtender now runs Dev Kit 0.3.0 copied from framework branch `dev/devkit-tools`; framework main is still 0.2.0. If the branch never merges, the next install-devkit from main would *downgrade* the game. *Fix:* the installer refuses to install a VERSION lower than the game's, and prints the source branch; /develop's version check names the branch; a "framework PRs waiting" line in STATE's Muzzy list (done by hand this time).
37. 🟢 **version.json never moves during /develop** (only /save bumps builds, and /deliver versions) — so Dev Kit snapshots and bug captures from a whole night of work are all stamped 0.0.0.0. *Fix:* /save bumps the build number every time (cheap), so captures can be matched to commits.
38. 🟡 **Kit gaps from pass-and-play (Sprint 04):** no player-tinted panel (Handoff overrides --primary locally), no local-game setup screen (built from Settings parts), Results has no per-player detail line and wraps 3 buttons, Modal has no wide size, PlayerChip changes height when its detail appears, HowToPlay allows one paragraph per page. Every local-multiplayer game will need these. *Fix (framework):* a "table game" kit pack — NewGame/SeatSetup, Handoff, detailed Results rows, player tones.
39. 🔴 **Roll Better (live) leaks every player's persistentId to all players** — anyone who reads it can claim that seat on rejoin and see that player's dice. Found while harvesting the rooms module (the new module never sends it). Roll Better is on the shelf; *fix:* when it's next touched, install the rooms module or stop broadcasting persistentId. Muzzy should know it's live.
40. 🟢 **Harvesting improved the original.** Lifting rooms into the framework surfaced 5 improvements (no persistentId leak, server decides "no such room", Wi-Fi-safe dev host, rejoin always reclaims, join-on-every-connect). The "prove in a game, then harvest" rule works — and harvest time is when to re-review security.
41. 🟡 **Random-game e2e runs are non-deterministic — a pass isn't proof.** The online e2e passed for the builder and failed for me (a reveal prompt ran off screen only when the tangle happened to be a certain way). *Fix:* e2e scripts take a fixed seed by default and a `--random N` mode that tries N seeds; layout invariants ("side column width never changes", "no text overflows") asserted directly, not only via whatever the random game happens to show.
42. 🟢 **Kit text can't break long single words** (HudText sets overflow-wrap: normal; PlayerChip is max-content and never truncates names). *Fix (framework):* overflow-wrap: anywhere on HUD text + name truncation with ellipsis on chips.
43. 🟢 **Security review per online feature paid off** — 5 real issues (incl. a P1 bag brute-force) that 157 tests and a leak-checking e2e didn't catch, because they were about *inference* and *abuse*, not data sent. *Fix:* /develop runs a threat-model review helper for any feature touching networking, randomness, or hidden information.
44. 🟢 **Muzzy's playtest notes were UI-craft rules, not one-offs** — drop-zone feedback (zone reacts vs piece reacts), finger-sized buttons tied to piece size, instructions placed at the point of action (not a disconnected header), turn indication on the pieces themselves, a "can't" shake, neutral word highlights *behind* content (border not frame), fewer end-screen choices. *Fix:* capture these as a **board-game interaction checklist** in the game-ui skill / framework (reusable across every board/card game), so the next game gets them by default instead of after a playtest.
45. 🟡 **Contradicting layout asks surface late.** "Prompt just above the tray" + "tray half as far from the board" can't both hold on tall phones; only found while building. *Fix:* /develop reads back a feedback list as a numbered plan with any conflicts called out *before* building (I read it back, but didn't spot this one).
46. 🔴 **"Check on your device" without a link.** /bug step 4 and /develop's hand-off ask Muzzy to confirm on his device but don't require the link — I did it twice in one session despite a saved memory. Muzzy: "that should be standard delivery process." *Fix:* /bug, /develop §4 and sprint-end hand-offs call /play's link block (PC + phone links, curl-checked, required servers started — incl. party:dev for online) every time they ask for a device check; a hand-off without links is incomplete.
47. 🔴 **Handed Muzzy links to a broken page.** A dev server running all night through hundreds of hot updates (helpers editing files) served a stale cached module → blank white screen ("does not provide an export named …"), while tests + build were green. Curl said 200. *Fix:* the link hand-off (see #46) must load the page in a real headless browser and check for page errors — not just curl — and restart the dev server (`--force`) after big helper edit bursts. /play's link block does this.
